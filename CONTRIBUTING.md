# Contributing to Site Studio
Feature requests, bugs, support requests, and milestones are tracked via the [GitHub issue queue](https://github.com/acquia/cohesion/issues).

Before submitting an issue or pull request, please read and take the time to understand this guide. Issues not adhering to these guidelines may be closed.

## Submitting issues

* Issues filed with this project are not subject to an SLA.
* Site Studio is distributed under the GPLv2 license; all documentation, code, and guidance is provided without warranty.
* The project maintainers are under no obligation to respond to support requests, feature requests, or pull requests.

## Submitting pull requests

Pull requests must also adhere to the following guidelines:
- PRs should be atomic and targeted at a single issue rather than broad-scope.
- PRs must contain clear testing steps and justification, as well as all other information required by the pull request template.
- PRs must pass automated tests before they will be reviewed. We recommend you run the tests locally before submitting (see below).
- PRs must comply with Drupal coding standards and best practices as defined by the project maintainers.

## Building and modifying the React application

Site Studio includes a React application that is bundled directly with
the Drupal module. Contributors who need to modify, patch, or rebuild
the React app should follow the instructions below.

### Application location

The React application source is located at:

    apps/react/

All required static assets (fonts, images, validation JSON files, and
other resources) are bundled with the application during the build
process. The application does not fetch these assets from an external
API at runtime.

### Installing dependencies

From the repository root, run:

``` bash
cd apps
npm install
```

### Building the application

#### Production build

``` bash
cd apps
npm run production
```

This command will:

-   Build the React application using webpack
-   Bundle all required assets with the application
-   Output the built files to:

```
js/react-app/
```

The generated `app.js` file is referenced by the Drupal library
configuration.

#### Production build for local Drupal development

``` bash
cd apps
npm run production-drupal
```

This performs the same build as the production command and ensures the
output is available for local Drupal development workflows.

#### Development build

``` bash
cd apps
npm run build
```

Builds the React application with source maps enabled.

#### Watch mode

``` bash
cd apps
npm run watch
```

Rebuilds the application automatically when source files change.

### Build output

After a successful build, the following directory structure is created:

    js/react-app/
    ├── app.js
    └── assets/
        ├── fonts/
        ├── images/
        ├── element-validation/
        ├── form-validation/
        └── js/

This directory is generated by the build process and is intentionally
tracked so that end users and contributors can rebuild the React
application as needed.

### Additional notes

-   React application assets are bundled at build time and are no longer
    fetched from an external API.
-   The `js/react-app/` directory is created automatically by the build
    process.
-   Legacy asset files that are no longer required are excluded from the
    build.
-   Build scripts do not copy React application files to the API; output
    is intended for use by the Drupal module only.
